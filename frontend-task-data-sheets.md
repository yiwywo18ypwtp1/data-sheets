# Тестовое задание: Data Sheets (Next.js + React)

Нужно сделать упрощённый Airtable: таблицы с типизированными колонками, редактируемая сетка на 50 000 строк, формулы со связями между ячейками, сохранённые представления, мастер импорта CSV и совместное редактирование в реальном времени.

Задание разбито на уровни. **Core** обязателен, **Advanced** показывает уровень, **Bonus** по желанию. Лучше меньше, но целостно, чем всё и наполовину.

---

## 0. Стек и ограничения

- **Next.js 15+ (App Router)**, React 19, TypeScript `strict`.
- Формы: **React Hook Form + zod**. Схемы общие для клиента и сервера.
- Виртуализация: TanStack Virtual или свой код. **Готовые data grid (AG Grid, Glide, Handsontable, MUI DataGrid и т. п.) нельзя**: сетка, выделение, редактирование и вставка это и есть задание.
- Парсер формул **свой** (рекурсивный спуск или Pratt). Библиотеки вычисления выражений (`mathjs`, `formula.js`, `hot-formula-parser`) нельзя. CSV-парсер можно взять (`papaparse`).
- Клиентское состояние сетки: на выбор (`useSyncExternalStore`, Zustand, Jotai). Выбор обосновать.
- API: mock внутри проекта (Route Handlers + SQLite). Realtime: SSE или WebSocket через свой Node-сервер.
- Тесты: Vitest + React Testing Library, Playwright для e2e.

## 1. Доменная модель

```ts
type Base = { id: string; name: string; tables: TableMeta[] };

type TableMeta = { id: string; name: string; primaryFieldId: string; fields: Field[]; views: View[]; version: number };

type Field =
  | { id: string; name: string; type: "text"; maxLength?: number }
  | { id: string; name: string; type: "number"; precision: 0 | 1 | 2 | 3 | 4; min?: number; max?: number }
  | { id: string; name: string; type: "currency"; currency: string }
  | { id: string; name: string; type: "date"; includeTime: boolean; timeZone?: string }
  | { id: string; name: string; type: "checkbox" }
  | { id: string; name: string; type: "singleSelect" | "multiSelect"; options: { id: string; label: string; color: string }[] }
  | { id: string; name: string; type: "email" | "url" }
  | { id: string; name: string; type: "link"; targetTableId: string; multiple: boolean }   // связь с записями другой таблицы
  | { id: string; name: string; type: "lookup"; linkFieldId: string; targetFieldId: string }
  | { id: string; name: string; type: "formula"; expression: string; resultType: "text" | "number" | "date" | "checkbox" };

type CellValue = string | number | boolean | string[] | null;   // для link и multiSelect это массив id
type Row = { id: string; values: Record<string /* fieldId */, CellValue>; createdAt: string; updatedAt: string; rev: number };

type View = {
  id: string; name: string; kind: "grid" | "form";
  filter: FilterGroup;                         // дерево AND/OR, как в Campaign Builder, но условия зависят от типа поля
  sorts: { fieldId: string; direction: "asc" | "desc" }[];
  groupBy?: { fieldId: string }[];             // до 2 уровней
  hiddenFieldIds: string[];
  fieldOrder: string[];
  columnWidths: Record<string, number>;
  rowHeight: "short" | "medium" | "tall";
};
```

Формулы ссылаются на поля по имени в фигурных скобках: `IF({Status} = "Done", {Price} * {Qty}, 0)`, `DATEADD({Start}, 7, "days")`, `CONCAT({First}, " ", {Last})`. Функции минимум: `IF`, `AND`, `OR`, `NOT`, `SUM`, `ROUND`, `CONCAT`, `LEN`, `UPPER`, `LOWER`, `DATEADD`, `DATETIME_DIFF`, `TODAY`, `BLANK`. Ссылка на поле по имени при сохранении превращается в ссылку по id, чтобы переименование поля не ломало формулу.

Текущий пользователь выбирается на `/settings` (cookie). Роли: `viewer`, `editor`, `creator` (может менять схему таблицы).

## 2. Страницы

### 2.1 `/b/[baseId]/[tableId]/[viewId]` — сетка (Core + Advanced)

- **50 000 строк × 30 колонок** в сиде. Виртуализация по строкам **и** по колонкам. Закреплённая первичная колонка и шапка.
- Данные грузятся окнами (по видимому диапазону строк), а не целиком. Фильтр, сортировка и группировка выполняются **на сервере**. Счётчик строк, сумма или среднее по числовым колонкам в футере.
- **Выделение**: ячейка, диапазон мышью и Shift+стрелки, вся колонка, вся строка. Видимая рамка выделения как в Excel.
- **Клавиатура**: стрелки, Tab, Enter начинает и завершает редактирование, Escape отменяет, ввод символа начинает редактирование с заменой, Delete очищает диапазон, Cmd/Ctrl+Home/End, PageUp/PageDown.
- **Редакторы по типу поля**: текст, число с форматом, денежное значение, дата и время в таймзоне поля, checkbox, select с поиском, multi-select, link с поиском записей другой таблицы. Невалидное значение не сохраняется, ячейка показывает ошибку.
- **Copy / paste**: копирование диапазона в TSV, вставка из Excel или Google Sheets с приведением типов (`"1 234,50"` в число, `"12/03/2026"` в дату с учётом локали, текст в select по совпадению метки). Вставка за пределы таблицы предлагает добавить строки. Ячейки, которые не удалось привести, подсвечиваются, а не превращаются молча в пустоту.
- **Fill handle**: протянуть значение или прогрессию чисел и дат вниз.
- **Undo / Redo** (Cmd+Z / Shift+Cmd+Z) для правок, вставки, удаления строк и fill. Одна вставка 500 ячеек отменяется одним действием. История на сессию.
- Изменения оптимистичные. Сервер отвечает батчами. При ошибке откатываются только затронутые ячейки, остальная работа не теряется.
- Добавление и удаление строк, изменение порядка и ширины колонок, скрытие колонок. Всё, что относится к представлению, сохраняется во view.
- **Группировка** до 2 уровней со сворачиванием групп и агрегатами в заголовке группы. Виртуализация продолжает работать при свёрнутых и развёрнутых группах.

### 2.2 Панель представления: фильтры, сортировки, поля (Core + Advanced)

- **React Hook Form**, одна форма на панель. Дерево фильтров на вложенных `useFieldArray`, до 2 уровней.
- Условие зависит от типа поля: для текста `contains / is / is empty`, для числа `= ≠ < > between`, для даты `is / before / after / within last N days / is today` в таймзоне поля, для select `is any of / is none of`, для link `has any of`. Смена поля сбрасывает оператор и значение без мусорных ключей.
- Сортировки: список с перетаскиванием и клавиатурой, без дублей полей.
- Применение фильтра к сетке с debounce. Состояние «есть несохранённые изменения представления» с кнопками сохранить или сбросить.
- Представление адресуется URL. Временный фильтр можно передать в query (`?filter=<base64>`), чтобы поделиться ссылкой без сохранения.

### 2.3 Схема таблицы и формулы (Core + Advanced)

- Создание, переименование, удаление и смена типа поля. Форма поля на RHF с discriminated union по `type`.
- **Смена типа поля** показывает превью: сколько значений сконвертируется, сколько станут пустыми, с примерами. Подтверждение, затем конвертация на сервере одной операцией.
- **Редактор формулы**: подсветка синтаксиса, автодополнение имён полей и функций, ошибка с позицией (`Unknown field "Prise" at 14`), живое превью результата на первых 5 строках.
- **Граф зависимостей**: формула, lookup и link образуют граф. Изменение ячейки пересчитывает только зависимые ячейки. **Циклы** обнаруживаются при сохранении формулы и показываются с путём (`Total → Tax → Total`).
- Пересчёт формул на сервере при записи, значения формул отдаются вместе со строками. Клиент пересчитывает зависимые формулы оптимистично в той же строке, сервер подтверждает.
- Удаление поля, на которое ссылаются формулы: показать, какие формулы сломаются, и не дать удалить без подтверждения. После удаления формулы показывают ошибку, а не падают.

### 2.4 `/b/[baseId]/[tableId]/import` — мастер импорта CSV (Core + Advanced)

- Шаг 1: загрузка файла до 20 МБ. Парсинг в **Web Worker** со стримингом и прогрессом, UI не блокируется. Определение разделителя и кодировки, превью первых 50 строк.
- Шаг 2: **сопоставление колонок**. RHF + `useFieldArray` по колонкам CSV: в существующее поле, в новое поле с выбранным типом, или пропустить. Автосопоставление по имени. Два CSV-столбца в одно поле запрещены.
- Шаг 3: **валидация**. Zod-схема строится в рантайме из сопоставления и типов полей. Таблица ошибок по строкам с возможностью поправить значение прямо в превью или выбрать стратегию: пропустить строку, импортировать пустым значением.
- Шаг 4: импорт батчами через Server Action с прогрессом, отменой и возобновлением после перезагрузки страницы (idempotency по номеру батча). Итог: импортировано, пропущено, с ошибками, со ссылкой на отчёт.
- Значения link сопоставляются с записями целевой таблицы по первичному полю. Ненайденные можно создать.

### 2.5 `/f/[viewId]` — публичная форма (Advanced)

- Представление типа `form` генерирует публичную страницу по полям таблицы: порядок, обязательность, подсказки и условная видимость настраиваются во view.
- Страница статическая с revalidate по тегу при изменении view или схемы. Zod-схема строится из полей в рантайме и на клиенте, и на сервере.
- Сабмит создаёт строку через Server Action, с idempotency key и защитой от спама (honeypot + rate limit по IP в моке).

### 2.6 Совместное редактирование (Advanced)

- Несколько вкладок или пользователей видят правки друг друга в течение секунды. Сервер рассылает изменения через SSE или WebSocket.
- **Presence**: цветная рамка вокруг ячейки, которую выделил другой пользователь, и аватары в шапке.
- **Конфликты на уровне ячейки**: у строки есть `rev`. Если два пользователя правят разные ячейки одной строки, обе правки применяются. Если одну ячейку, побеждает последняя запись на сервере, а проигравший видит тост с его значением и кнопкой «вернуть моё».
- Удалённые другим пользователем строки исчезают у всех. Если в этот момент строка редактируется, редактор закрывается с объяснением.
- Изменение схемы таблицы другим пользователем применяется без перезагрузки страницы. Если удалили поле, которое у вас открыто в редакторе, форма закрывается с объяснением.
- Обрыв соединения: индикатор, очередь локальных правок, повторная отправка и догрузка пропущенных событий по последнему полученному номеру.

## 3. API (mock)

Ошибки в едином формате `{ error: { code, message, fieldErrors?, details? } }`.

| Метод | Путь | Заметки |
|---|---|---|
| GET | `/api/tables/:id` | схема, представления, `ETag` |
| GET | `/api/tables/:id/rows?viewId&offset&limit&filter&sort&group` | окно строк + `total` + агрегаты; `limit ≤ 500` |
| POST | `/api/tables/:id/rows/batch` | `{ ops: [{ op: "update" \| "create" \| "delete", rowId, values, rev }] }` до 1000 операций, частичный результат |
| POST | `/api/tables/:id/fields` | создание поля, формула валидируется на сервере |
| PATCH | `/api/tables/:id/fields/:fieldId` | `?preview=1` возвращает превью конвертации типа |
| DELETE | `/api/tables/:id/fields/:fieldId` | `409` с зависимыми формулами без `?force=1` |
| PUT | `/api/views/:id` | `If-Match` |
| POST | `/api/formula/check` | `{ tableId, expression }` → тип результата, зависимости, ошибка с позицией |
| GET | `/api/tables/:id/records/search?q` | для редактора link |
| POST | `/api/tables/:id/import` | батч, заголовок `Idempotency-Key` |
| GET | `/api/tables/:id/events?since=` | SSE-поток изменений с номером события |
| POST | `/api/forms/:viewId` | публичный сабмит |

Env для симуляции: `MOCK_LATENCY_MS`, `MOCK_FAILURE_RATE`, `MOCK_NOW`, `REALTIME_DROP_RATE` (доля событий, которые сервер «теряет», чтобы проверить догрузку).

Сид: база из 3 таблиц (Orders 50 000 строк, Customers 5 000, Products 500), связи между ними, 5 формул, 2 lookup, по 3 представления на таблицу.

## 4. Нефункциональные требования

- **Производительность сетки**: прокрутка 50 000 × 30 без пропуска кадров; ввод в ячейку и перемещение выделения не перерисовывают другие строки; вставка 10 000 ячеек не блокирует UI больше чем на 100 мс подряд. Приложить замеры (Performance, Profiler, long tasks) и как их воспроизвести.
- **Память**: открытая таблица держит в памяти только окна строк около видимой области, а не все 50 000. Описать стратегию вытеснения.
- **RSC/Client split**: что рендерится на сервере (каркас, панели, метаданные), что на клиенте и почему. Таблица в `ARCHITECTURE.md`.
- **Кеширование**: схема таблицы, окна строк, публичная форма. Что инвалидирует что.
- **Доступность**: сетка с ролями `grid`, `row`, `gridcell`, `aria-rowcount` и `aria-colcount` для виртуализированных данных, `aria-selected`, объявление результата вставки и undo через `aria-live`.
- **Локаль и время**: числа и даты форматируются по локали пользователя, хранятся в нейтральном виде. Тесты гоняются в двух таймзонах (`TZ=Pacific/Auckland`, `TZ=America/Los_Angeles`) с одинаковым результатом.

## 5. Тесты

- **Unit**: лексер и парсер формул, вычисление с типами и пустыми значениями, обнаружение циклов и порядок пересчёта; приведение типов при вставке и импорте; конвертация типа поля; стек undo/redo с батчами; разрешение конфликтов по `rev`; сериализация фильтра в URL и обратно.
- **Component (RTL)**: навигация клавиатурой и редактирование ячейки; дерево фильтров со сменой типа поля; шаг сопоставления колонок в импорте.
- **E2E (Playwright)**, минимум 4:
  1. отфильтровать, отсортировать, сохранить представление, перезагрузить: вид тот же;
  2. вставить диапазон из буфера, отменить одним Cmd+Z, вернуть Shift+Cmd+Z;
  3. импорт CSV с ошибками: поправить одну в превью, остальные пропустить, проверить итог;
  4. две вкладки правят одну строку: разные ячейки сливаются, одна ячейка показывает конфликт.

## 6. Уровни

**Core:** 2.1 без группировки, fill handle и undo для удаления строк; 2.2 без перетаскивания сортировок и без фильтра в URL; 2.3 без смены типа поля, редактор формулы без подсветки и автодополнения, но с циклами и пересчётом; 2.4 шаги 1–4 без возобновления после перезагрузки и без link; API; unit-тесты формул и приведения типов; `README.md` и `ARCHITECTURE.md`.

**Advanced:** всё из 2.1–2.6 целиком, RTL и e2e.

**Bonus:** kanban-представление по single select с перетаскиванием между колонками; история изменений ячейки; экспорт представления в CSV стримом; офлайн-режим с IndexedDB; комментарии к строке с упоминаниями.

## 8. Edge cases, которые мы проверим руками

- `?filter=garbage`, `viewId` от другой таблицы, `offset=-1`, `limit=100000`.
- Формулы: `{A} / 0`, `IF({Empty}, 1)`, цикл через три поля, ссылка на поле из другой таблицы, 200 вложенных скобок, строка длиной 100 000 символов.
- Переименовать поле, на которое ссылается формула; удалить его.
- Вставить из Google Sheets 3 × 1000 ячеек со смешанными типами, где часть значений невалидна; вставить один столбец в выделение из пяти.
- Сменить тип поля `text` на `number`, где 30% значений не числа; затем обратно.
- Дата `2026-03-29 02:30` в поле с таймзоной `Europe/Berlin` (несуществующее время) и `2026-10-25 02:30` (повторяющееся время).
- Импорт CSV в `Windows-1251` с разделителем `;` и BOM; файл в 20 МБ; закрыть вкладку на середине импорта и открыть снова.
- Отфильтровать по формуле, которая зависит от lookup; поменять значение в связанной таблице и проверить, что строка пропала или появилась в фильтре.
- Прокрутить в конец 50 000 строк, Cmd+Z после этого откатывает правку из начала таблицы и показывает её.
- Две вкладки: одна удаляет строку, пока вторая её редактирует; одна удаляет поле, пока вторая настраивает по нему фильтр.
- `REALTIME_DROP_RATE=0.3`: через минуту правок обе вкладки показывают одно и то же.
- Публичная форма: двойной сабмит при `MOCK_LATENCY_MS=3000`; схему поменяли, пока гость заполнял форму.
